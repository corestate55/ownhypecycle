# 要件定義

## 目的

ガートナー ハイプサイクルを自作できるブラウザアプリを提供する。
キーワードとそのフェーズ・実現時期を入力し、ハイプサイクル曲線上に視覚化する。

## 画面構成

画面を上下に分割する。

- **上部**: ハイプサイクル SVG チャート
- **下部**: キーワード管理テーブル

## データモデル

### エントリ (Entry)

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `id` | string (UUID) | 一意識別子（内部管理のみ。CSV/JSON エクスポートには含まない） |
| `keyword` | string | 表示するキーワード |
| `timeToAdoption` | TimeToAdoption | 想定される実現時期 |
| `stage` | Stage | ライフサイクルのどの段階にあるか |
| `position` | number [0, 1] | **フェーズ内**の相対位置（0=フェーズ開始、1=フェーズ終了） |

### ライフサイクルのフェーズ (Stage)

| 値 | 日本語名 | 英語名 |
|----|---------|--------|
| `innovation_trigger` | 黎明期 | Innovation Trigger |
| `peak_of_expectations` | 「過度な期待」のピーク期 | Peak of Inflated Expectations |
| `trough_of_disillusionment` | 幻滅期 | Trough of Disillusionment |
| `slope_of_enlightenment` | 啓発期 | Slope of Enlightenment |
| `plateau_of_productivity` | 生産性の安定期 | Plateau of Productivity |

### 想定される実現時期 (TimeToAdoption)

| 値 | 意味 | 記号 |
|----|------|------|
| `lt2` | 2年未満 | 白塗り丸（黒枠）○ |
| `2to5` | 2〜5年 | 青塗り丸 ● |
| `5to10` | 5〜10年 | 紺塗り丸 ● |
| `gt10` | 10年以上 | 赤塗り三角 ▲ |
| `obsolete` | 安定期に達する前に陳腐化 | 赤線バツ丸 ⊗（丸＋斜め2本線） |

## 機能要件

### チャート表示

- ハイプサイクルの特徴的な曲線（本家 Gartner に近似した形状）を描画する
- 5つのフェーズの区切り線と名称をチャート下部に表示する
- テーブルのエントリをリアルタイムで曲線上に描画する
- 各エントリは **実現時期アイコンを曲線上に直接配置** し、キーワードラベルをアイコンの横に表示する
- ラベルが他のラベルと重なる場合は Y 方向に押し出し、曲線上のアイコンとスパイク線で結ぶ
- 実現時期の凡例をチャート右上に縦並びで表示する

### インタラクション（ドラッグ操作）

- チャート上の実現時期アイコンをドラッグして位置を変更できる
- ドラッグ可能な範囲は、そのエントリが所属するフェーズの X 区間に限定する
- ドラッグ中にテーブルの `position` 値がリアルタイムで更新される

### テーブル操作

- 行の追加（デフォルト値でエントリを追加）
- 行の削除
- 各セルのインライン編集（クリックで入力フィールドに切り替え）
  - キーワード: 1文字入力するたびにチャートへ即時反映
  - 実現時期・フェーズ: ドロップダウン選択で即時反映
  - 位置 [0,1]: 数値を入力・確定するとチャートに反映

### データのインポート・エクスポート

| 操作 | 形式 | 方法 |
|------|------|------|
| エクスポート | CSV | Blob + `<a download>` |
| エクスポート | JSON | Blob + `<a download>` |
| インポート | CSV / JSON | `<input type="file">` → FileReader |
| 図のエクスポート | SVG | SVG ノードをシリアライズして `<a download>` |

CSV・JSON の列/フィールド順は `id` を除く Entry の全フィールドとする。
インポート時は既存データを上書きする。

### データの永続化

- データの永続化は**行わない**
- ページを閉じるとデータは消える
- localStorage も使わない

## 非機能要件

- コンテナ（Docker）で配布可能な構成とする
- バックエンドは不要。すべてクライアントサイドで完結する
- モダンブラウザ（Chrome / Firefox / Safari 最新版）で動作する
